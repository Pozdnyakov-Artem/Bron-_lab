# БроньЛаб на сервере

Адрес: **https://185.153.183.233:8443/**. Обычный HTTP перенаправляет сюда. Порт 443 занят существующим VPN (xray); сайт использует 8443. При настройке портов VPN не изменялся.

Развёрнуто 6 октября 2026 года на Ubuntu 24.04, Python 3.12, Nginx 1.24, Waitress. Приложение работает под системным пользователем `bronylab` и слушает только localhost:8000; внешний доступ идёт через Nginx. Проверены вход, каталог, занятость, подтверждение, конфликт, повторная заявка и выход через публичный HTTPS. Все 53 теста прошли и на сервере.

## Доступ

На сервере созданы новые случайные пароли для `admin-01`, `student-01`, `teacher-01`. Демонстрационные пароли из README здесь не действуют. Данные доступа переданы владельцу отдельно в `bronylab-server-access.md`; этот файл не входит в архив исходников и не опубликован на сайте.

## Расположение

| Данные | Путь |
|---|---|
| Исходники выпуска | `/opt/bronylab/releases/20261019-02/bronylab` |
| Текущий выпуск | `/opt/bronylab/current` |
| Python-окружение приложения | `/opt/bronylab/venv-0.2.1` |
| Рабочая конфигурация | `/etc/bronylab/config.yaml` |
| Защищённые переменные окружения | `/etc/bronylab/bronylab.env` |
| База данных | `/var/lib/bronylab/bronylab.sqlite3` |
| Лог операций | `/var/log/bronylab/bronylab.log` |
| Конфигурация Nginx | `/etc/nginx/sites-available/bronylab` |
| Резервные копии | `/var/backups/bronylab` |
| HTTPS-сертификат | `/etc/letsencrypt/live/bronylab-ip` |

Приложение запускается `bronylab.service` с автозапуском, перезапуском при ошибках и доступом на запись только к своим каталогам данных и логов. Режим `BRONYLAB_HTTPS=1` включает Secure-cookie. `BRONYLAB_TRUST_PROXY=1` доверяет только локальному Nginx; заголовки реального IP и схемы HTTPS устанавливает сам Nginx.

## Управление через SSH

Подключение: `ssh -i /путь/к/вашему/ключу root@185.153.183.233`. Приватный SSH-ключ не копировался на сервер и не включён в проект.

```bash
systemctl status bronylab
systemctl restart bronylab
journalctl -u bronylab -n 100 --no-pager
nginx -t
systemctl reload nginx
```

После изменения YAML перезапустите приложение. Для нового пользователя сначала добавьте его в `users` или `admin_users`, затем:

```bash
/opt/bronylab/venv-0.2.1/bin/bronylab set-password --config /etc/bronylab/config.yaml --user USER_ID
systemctl restart bronylab
```

Команда запрашивает пароль интерактивно. Пароль сохраняется в SQLite; YAML-хеш используется только при первичном создании аккаунта. Не меняйте его вручную в YAML, ожидая обновления существующего пароля.

## HTTPS и продление

Используется доверенный сертификат Let's Encrypt непосредственно для IP-адреса. Сертификаты этого типа действуют примерно шесть дней, поэтому важно автоматическое продление. Таймер `bronylab-cert-renew.timer` проверяет необходимость продления дважды в сутки; deploy-hook проверяет и перезагружает Nginx. HTTP-порт 80 нужен для ACME-проверки и редиректа.

```bash
systemctl list-timers bronylab-cert-renew.timer
journalctl -u bronylab-cert-renew.service --no-pager
/opt/bronylab/certbot-venv/bin/certbot certificates
/opt/bronylab/certbot-venv/bin/certbot renew --dry-run --run-deploy-hooks --cert-name bronylab-ip
```

Документация механизма: [IP-сертификаты Let's Encrypt и Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).

## Резервные копии

`bronylab-backup.timer` делает ежедневную копию SQLite через backup API и проверяет её целостность. Сохраняет 14 дней копий в `/var/backups/bronylab`; файлы доступны только служебному пользователю и root. Первая копия создана и проверена. Время сервера — UTC, запуск около 02:00 UTC (09:00 Новосибирска), со случайной задержкой до 15 минут.

```bash
systemctl start bronylab-backup.service
systemctl list-timers bronylab-backup.timer
journalctl -u bronylab-backup.service -n 20 --no-pager
```

Копии находятся на том же сервере. Для защиты от потери VPS периодически выгружайте их в своё отдельное хранилище. Перед восстановлением остановите `bronylab`, замените файл базы выбранной копией, установите владельца `bronylab:bronylab` и права 600, затем запустите сервис. Конфигурацию и файл окружения сохраняйте отдельно в защищённом месте.

Проверочная бронь, созданная при публикации, удалена из рабочей базы после сохранения записи и восстановимой копии. Рабочая база не содержит демонстрационных броней локальной версии.
